- **PARKED — do when the user is back (their words: "fix those three things later when i am back", 2026-08-11).** Measured Keka's UI directly via `getComputedStyle`: **Proxima Nova, 13px / 20px line-height / weight 400**, ink `#0F1824` on `#F9FAFB`, muted `#848F9F`. The user asked "maybe it's the font" — diagnosis is that the typeface is the *smallest* factor. The three fixes, in order of impact:
  1. **Weight restraint.** Keka is 400 nearly everywhere — even its 20px metric ("0h") is weight 400. We lean 600–700 on headings/labels. This is the main reason ours reads louder/more mechanical.
  2. **Column headers.** Keka's are **sentence-case, regular weight, muted grey**. Ours are **uppercase mono with letter-spacing** — the "engineered register" choice now looks harsh by comparison. Soften.
  3. **Density.** Keka is 13/20; ours is 13.5–14.5. Tighten.
  Optional 4th: trial a warmer **humanist** face against Hanken Grotesk (a neo-grotesque, colder by design). Proxima Nova is licensed/not free — closest free analogues: Nunito Sans, Source Sans 3, Mulish. **Judge the typeface separately from the weight change** or the two confound.
  ALSO parked: draw the **expressive glyph set** — Keka's **tortoise** (thin amber outline + exact lateness, e.g. "1:29:24 late"), **smiley** (worked weekly-off), **amber `!`** (missing punch). Close-up saved at `design/reference/keka/glyph-tortoise-late-zoom.png`. The user has asked for these three times; they're the biggest single reason Keka reads human. Draw ours in the same thin-outline language — never emoji.
