`design/kit.jsx` exposes `window.UI` — a self-contained component kit built on `window.G` (Peacock & Slate tokens, see [naveya token system](project_naveya_token_system.md)): a React-context `ThemeProvider`/`useTheme()`/`ThemeToggle` (mode lives in provider state; `useTheme()` returns `{mode, c, toggle, mo, el, reduced}`; `prefers-reduced-motion` swaps in `G.mo.reduced` automatically), `Button` (primary/accent/ghost/link/icon variants), `Field`/`Input`/`Select`/`Search` (shared accent-alpha focus ring via `c.focus`), `Mark` (P/A/L/H shape+color), `Badge`/`StatusPill` (status→tone+icon mapping centralized here so screens never encode state by hue alone), `Card` (elevation via `G.el[mode]`, dark uses the `G.surf` ladder), `SectionHeader`, `BilingualLabel` (danda-separated EN/Deva via `G.t(role,'deva')`), `Figure` (tabular-mono ₹), `Register` (the hero muster grid — structural "laal kinaara" record-rule column is a real `display:grid` column, never a card `border-left`), `Ledger`, `Avatar`, `Seal`, `Icon` (square-terminal SVG set: home/calendar/wallet/document/user/bell/check/chevron/search/plus/logout/alert/clock/sun/moon), and `withAlpha` (hex→rgba helper, exported so other `design/*.jsx` files like `design-canvas.jsx` can reuse it without re-implementing).

`design/screens.jsx` exposes `window.Screens = { Login, Employee, AdminStub }` and composes ONLY from `window.UI` — no raw hex, no bespoke buttons/inputs. `design/design-canvas.jsx` (the pan/zoom board, `window.NaveyaBoard`) and `design/prototype.jsx` (the real router) both wrap their tree in a SINGLE `<UI.ThemeProvider>` and consume the kit/screens; script load order is always `tokens.jsx → kit.jsx → screens.jsx → (design-canvas.jsx | prototype.jsx)`.

**Why:** this dispatch (2026-07-22) retired `design/hi-fi/hi-fi.jsx`'s monolithic-file pattern (one 1500-line IIFE mixing tokens+chrome+screens) in favor of a layered kit→screens→app split, matching how the eventual `frontend/` component library should be organized.

**How to apply:** for any future `design/*.jsx` work, extend `kit.jsx` for new reusable primitives (don't hand-roll a one-off button/input inside a screen) and extend `screens.jsx` for new full views, keeping the same classic-JSX-runtime/no-imports/inline-styles constraints from [design-canvas conventions](project_design_canvas_conventions.md). `design/hi-fi/hi-fi.jsx` and `design/playground.*` are NOT deleted (left as historical/reference artifacts per direct instruction) but are no longer loaded by `index.html`/`prototype.html`.

**2026-07-22 impeccable-critique fix sweep additions to `window.UI`:** `Spinner` + `Button({loading})` (spinner prepends children, `aria-busy`, disables via `loading||disabled` — never hand-roll a pending-button state in a screen); a **global `:focus-visible` stylesheet** injected by `ThemeProvider`'s `useEffect` (one `<style id="tn-kit-global-style">` tag, `outline: 2px solid ${c.focus}` re-written on every theme change — this is the ONE place the ring color is authored, `index.html`/`prototype.html` no longer hardcode a duplicate `button:focus-visible` rule); `@keyframes tn-spin`/`tn-pulse` in that same tag back both `Spinner` and the new `Skeleton`; `Field` gained `onLabelAction` (its `labelAction` is now a real `<button>`, not a dead `<span>`); and `MaskedValue`/`Textarea`/`DaySegmented`/`EmptyState` were promoted from private per-screen copies (documents.jsx+profile.jsx had duplicate `MaskedValue`; leave.jsx had `Textarea`+`DaySegmented`).
