Built 2026-08-11: `design/canvas.html` + `design/canvas.jsx`, a pan/zoom board distinct from `design/index.html`/`design-canvas.jsx` (which renders live React screen *components* inside the same document). This board instead embeds each screen's real standalone URL in its own `<iframe>` — own document, own theme/lang state, zero style leakage — scaled from a 1440×900 viewport down to a 460×288 thumbnail via `transform: scale()` + `transformOrigin: "top left"`, clipped by an `overflow: hidden` wrapper.

Key implementation notes for extending this board:
- **Self-contained by design** — `canvas.jsx` does NOT load `window.G`/`G2`/`UI`/`UI2`; it defines its own tiny local color/font const objects. `canvas.html`'s only script dependency is `canvas.jsx` itself (plus the standard React/ReactDOM/Babel CDN + `tenure` classic-JSX preset, copied verbatim from `v2.html`).
- **Lane/frame data lives in one array (`LANES`)** in `canvas.jsx` — flip a frame's `url` from `null` to a real path the moment a screen is built; counts in the header derive from this array, never hardcode the count.
- **Lazy iframe src** via a per-frame `IntersectionObserver` (`root: null`, so it watches the real browser viewport — this DOES correctly recompute across CSS-transform pan/zoom, no special-casing needed) + `loading="lazy"` belt-and-suspenders. Placeholder text shown until near-viewport.
- **`pointerEvents: "none"` on every iframe** — required so dragging that starts over an embedded screen thumbnail still pans the whole board instead of being swallowed by the iframe's own document; label bars use `data-nopan="true"` (lowercase — matches the actual DOM attribute name, since HTML lowercases attribute names regardless of JSX casing) so clicking a frame's title opens the real URL in a new tab without also triggering a pan-drag.
- Ghost ("not built") frames: dashed border, muted "Not built" chip, no iframe at all — same footprint as a built frame so the whole board reads as a coverage map at a glance.
- See [[feedback-react18-batched-setstate-ref-race]] for a real crash bug hit (and fixed) in this file's pan/zoom drag handler.

**2026-08-11 rebuild — three-state model, not two.** When v3 (Peacock) became canonical and v2's register-grammar screens were rejected, the board needed a THIRD frame state beyond built/ghost: `preV3: true` on a frame marks it "real content, but old system, kept only as reference" (currently `R1` payroll-run-console and `G1` overview-board, both `v2-x*.html` experiments the user explicitly liked and wanted kept). Render it with a small muted chip in the label row (`PreV3Chip`, gold-toned) — never silently show old-system chrome next to new-system chrome with no marker. Counts split three ways: `V3_COUNT` (canonical, no `preV3`), `PREV3_COUNT` (`url` + `preV3`), `TOTAL_COUNT` (all frames) — still fully derived, never hardcoded. Frames whose `url` pointed at REJECTED work (the old `v2-prototype.html?route=…` employee/principal screens) were deleted outright, not just re-flagged — a ghost (`url: null`) is the correct state for "not yet rebuilt," not a pointer to work the user rejected.
**Screen inventory is not authoritative — re-derive it from the spec each time the canonical system changes.** The user was explicit: don't treat the existing lane list as ground truth. Re-reading `docs/development-specification.md` M1–M17 + `docs/functionality-blueprint.md` against the *previous* lane list surfaced real gaps (recruitment split into 3 stages, loans/reimbursements/arrears, statutory filings, appraisal cycles M17, helpdesk M15.1, academic calendar M7, org/roles/integrations) — grew the board from 34 to 50 frames across the same 7 role lanes. Tag each lane with its module numbers (`M8 M9 M17` etc.) in the lane header so the mapping back to spec sections stays visible on the board itself.
**Retiring a lane is sometimes the fix, not adding to it.** Lane 8 "Explorations" (alternates, `picked` chip) was removed entirely once the design direction was settled — keeping resolved comparison material on a coverage-map board caused the exact "which is current" confusion the user complained about. Dead code (`PickedChip`, `CheckMark`, the `picked` prop) was deleted with it, not left dangling.
