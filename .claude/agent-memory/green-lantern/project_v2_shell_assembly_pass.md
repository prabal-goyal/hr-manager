Phase 3 of the STAFFROOM v2 build ([[project_staffroom_v2_build]]) wired six independently-built `design/v2/pages/*.jsx` content screens (Dashboard/Attendance/Leave/Payslips/Documents+Profile/Substitution) into a real shell + prototype:
- `design/v2/shell.jsx` (`window.Shell2`) — extracted verbatim from the user-approved `design/v2/variants/home-a.jsx` rail+topbar ([[project_home_variant_a_keka_rail]]), NOT the mockup's 214px text rail. Re-colours automatically since home-a.jsx already read `c.shell`/`c.shellActive` etc from the *current* `window.G2` — no new hex needed. Added a 7th nav item (`substitution`) + a `swap` icon glyph to `kit.jsx`'s shared `Icon`, and `nav.substitution` to the central `STRINGS` table (didn't do a page-local overlay — nav labels are chrome-level, belong centrally).
- `design/v2/prototype.jsx` + `design/v2-prototype.html` — Login (bypassable via clicking the "Sign in with school SSO" ghost button, which skips password validation entirely — useful for puppeteer scripts too) → `Shell2` with a plain route-key switch over `window.Pages2.*`.

**The one real inconsistency across the six blind-built pages:** only `dashboard.jsx` had duplicated chrome-level `ThemeToggle`+`LangSwitcher` (as a `LangCapsule` wrapper) inside its own `ActionBar`, because its author didn't yet know a shell would supply them ([[feedback_theme_toggle_single_instance]] — this is the second time this exact mistake has been made independently). The other five pages correctly kept their `ActionBar` to page-local actions only (download, badges, campus select). Fix: delete the duplicate controls + their now-dead imports, keep genuinely page-local controls (e.g. `CampusPicker` — content-relevant, unlike a global lang/theme toggle) — don't touch the other five pages, they were already right.

**Scroll-slot trick for a shared shell wrapping self-authored pages:** some content pages set `height:"100%"` on their own root (self-scrolling registers with a pinned header+footer around one internal `overflowY:auto` region — e.g. attendance, substitution, docsprofile), others set `minHeight:"100%"` (simple pages that just grow — dashboard, leave). A shell content slot of `{flex:"1 1 auto", minHeight:0, overflow:"auto"}` (NOT `overflow:"hidden"`, NOT wrapping children in another flex column) satisfies both without a double scrollbar: a `height:100%` child fills the slot exactly and scrolls internally; a `minHeight:100%` child that grows taller triggers the slot's own scrollbar. Verify by driving every route with real clicks, not just eyeballing one screen.

**Puppeteer verification at scale (7 routes × 3 language/theme passes = 21 shots):** added `data-nvx="nav-<key>"` to shell rail buttons, `data-nvx="theme"` to `ThemeToggle`, `data-nvx="lang-<code>"` to `LangSwitcher` buttons (matches an existing `data-nvx` convention already used in `design/v2/experiments/`) — these survive language switches (buttons keep their attribute regardless of visible text), so one script can drive light-EN → dark-EN → light-HI across every route without text-matching fragility. Also confirmed full-bleed programmatically, not just visually: `page.evaluate` counting DOM divs wider than 1300px on a 1440px viewport per route — a real check for "no dead side margins" beyond screenshot eyeballing.
