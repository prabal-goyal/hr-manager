Built `design/v3/pages/attendance.jsx` (`window.Pages3.Attendance`), wired into `design/v3.html` via `?screen=attendance` (only file besides the new page allowed to change per the dispatch). Establishes the convention for future v3 screens (Leave, Payslips, Documents, Profile): a standalone `design/v3/pages/<name>.jsx` file, classic-JSX IIFE, composed only from `window.G3`/`window.UI3`, exporting onto `window.Pages3.<Name>`, loaded in `v3.html` **after** `screens.jsx` (so it can read/extend the shared `STRINGS` dict but never needs to). `screens.jsx`/`tokens.jsx`/`kit.jsx` stay untouched.

Two structural decisions worth reusing:
1. **Date-derived weekdays, never hand-authored.** Every day record is generated by iterating real `Date` objects (`date.getDay()`) rather than manually assigning a `wd` field — this is provably correct and, cross-checked against `screens.jsx`'s hand-authored `ATT` mock (which used manual `wd` fields), reproduced the exact same weekday values, confirming both the technique and the original mock were right. See [[feedback-elapsed-vs-future-summary-leak]] for the bug this generation approach still let through (elapsed-filtering) and how it was caught.
2. **Shape-then-register-then-detail is a reusable three-tier pattern** for any Naveya register screen: a compact bar/token strip (`MonthShape`) for "shape first", a `<Register>` (kit component) for the exact ledger, and a narrow selected-item detail Card (matches Home's `colNarrow` rhythm) for drill-down + the screen's one action. Clicking either the shape or a register row's date cell (wrapped in an inline `<button>`, since `Register`'s `<tr>` has no click prop) updates the same `selectedDay` state — `Register`'s existing `row.highlight` prop does double duty as the "selected" indicator.

Money-to-attendance tie-in: the LOP day-rate is derived (`MONTHLY_GROSS_REF / 30`, referencing Home's mocked July gross of ₹1,04,600) rather than a separately hand-typed number — keeps the two screens' mock data implicitly consistent without literally sharing a module (`v2`/`v3` pages are still string-and-data self-contained per screen, per [[project-v3-canonical-peacock]]).
