`design/v3/kit.jsx` additions from the Attendance row-menu dispatch (2026-08-11), all exported on `window.UI3`:

- **`ActionMenu({ ariaLabel, items, glyph, size })`** — a "⋯"/"⋮" trigger + popover, rendered via `ReactDOM.createPortal(..., document.body)` with `position: fixed` computed from the trigger's `getBoundingClientRect()` (flips above the trigger if there isn't room below). This is the general escape-hatch for "a menu inside a narrow table cell/card that must not be clipped by the ancestor's layout" — used both as the Register row's per-row action menu AND a section header's kebab menu (Requests tab) with zero extra code, just a different `items` array. `items: [{ key, icon, label, disabled, reason, onSelect }]` — a `disabled` item stays IN the menu, dimmed, with `reason` printed under the label (never hidden) per `docs/ui-compliance-requirements.md`'s absent/disabled/offered rule. Full roving-tabindex keyboard model: Arrow Up/Down/Home/End move between items (including disabled ones, so they're still discoverable/announced), Enter/Space activates only if enabled, Escape closes and returns focus to the trigger, outside-click and window scroll/resize also close it.
- **`Switch({ checked, onChange, label, id })`** — a real toggle (not a checkbox skin), `role="switch"`, keyboard-operable. For binary DISPLAY preferences only (e.g. 24-hour format) — never wire it to an action that changes a record; those stay Buttons under the maker-checker/idempotency rules.
- **`Tabs({ items, active, onChange, ariaLabel })`** — plain text tab row, underline + weight on the active tab, `role="tablist"`/`"tab"`/`aria-selected`. Content switch only, never a route change.
- **`DayTimeline`** gained a `compact` + `height` prop (skips the hour-tick row, lets the caller set bar height) so the same component serves both the full day-detail timeline and a tiny per-row "attendance visual" mini-bar in a Register cell — one segments-drawing implementation, two densities.

**Icon set — thin-stroke pass:** `Icon`'s default `strokeWidth` moved from a bare `1.6` to `1.7` and every ad hoc per-call override inside kit.jsx that had crept to `2`/`2.1` (StatusMark's glyph, Seal's check, WelcomeBand's figure-note icon) was removed so they inherit the shared default — "consistent optical weight," not a heavier accent on some icons and not others. `BoatMark` (brand mark) and `DeskArt` (empty-state illustration) were deliberately left alone — they're custom SVGs outside the `Icon` component, not part of the interface icon set. New icons added for the row-menu's actions: `more` (three filled dots — the one deliberate fill exception, a 1px stroked ring is illegible at 14-18px), `briefcase` (on duty), `half` (partial day — a circle with one filled semicircle, reads as "half" the way a contrast/battery icon does), `list` (view day logs, same filled-dot-bullet exception as `more`), `globe` (web clock-in). "Request leave" and "Attendance policy" reuse the existing `leave` and `document` icons rather than adding near-duplicates.

**Known residual inconsistency:** `design/v3/screens.jsx` (Home/Login) still has three `Icon ... strokeWidth="2"` call sites (a status chip glyph, two alert icons) that were NOT normalized, because this dispatch's file scope explicitly excluded `screens.jsx`. Fold that into the next `screens.jsx`-touching dispatch rather than treating the icon set as fully unified yet.

**2026-09-03 correction:** the `Tabs` shipped in that pass was only HALF an ARIA tab pattern — `role="tablist"`/`role="tab"` with no `role="tabpanel"`, no ids, no `aria-controls`/`aria-labelledby`, no roving tabindex. Fixed by adding `UI3.TabPanel`; **`Tabs` and `TabPanel` must always be used as a pair with a shared `idBase`.** Because panels render lazily (one at a time), `aria-controls` is set only on the SELECTED tab — a dangling IDREF is a worse defect than an omitted optional attribute.
